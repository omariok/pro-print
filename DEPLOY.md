# Про-Принт — хостинг, домен, почта и эксплуатация

Сайт живёт на **https://pro-print.pro**. Этот файл — всё, что нужно знать, чтобы
продолжить работу с другого компьютера. Паролей здесь нет и быть не должно:
они хранятся только в панелях Timeweb, reg.ru и Яндекса.

## Схема

| Что | Где | Детали |
|---|---|---|
| Код | GitHub `omariok/pro-print` (приватный) | ветка `main`, пуш в неё = автодеплой |
| Хостинг | Timeweb Cloud, **App Platform** | приложение `pro-print`, ID 257655, аккаунт `db871100` |
| Домен | reg.ru | `pro-print.pro`, DNS на ns1/ns2.reg.ru |
| Почта заявок | Яндекс | ящик `pr0print@yandex.ru`, отправка через SMTP |

Панель приложения: https://timeweb.cloud/my/apps/257655

  отвечать, хостинг перезапустит его сам.
- Автодеплой: любой пуш в `main` пересобирает сайт (3–5 минут). Ход сборки —

  публичный IP `194.87.133.155`.
- Переменные окружения (Настройки → Настройки деплоя → Переменные):
  - `SMTP_USER` = `pr0print@yandex.ru`
  - `SMTP_PASS` = пароль приложения Яндекса (не пароль от аккаунта)
  - необязательные: `SMTP_HOST` (по умолчанию `smtp.yandex.ru`), `SMTP_PORT` (465),
    `MAIL_TO` (куда слать заявки; по умолчанию адрес из `src/lib/content/contact-info.ts`).
- Домены привязаны в Настройки → Домены: `pro-print.pro`, `www.pro-print.pro`

## Домен (reg.ru)

Зона управляется в личном кабинете reg.ru («Мои домены» → pro-print.pro →
управление зоной). Записи:

| Имя | Тип | Значение |
|---|---|---|
| `@` | A | `194.87.133.155` |
| `www` | A | `194.87.133.155` |

AAAA-записей (IPv6) быть не должно — иначе часть посетителей попадёт на
заглушку reg.ru. Если IP приложения в Timeweb изменится — поменять обе записи
и подождать (кеш DNS у провайдеров живёт до суток).

## Почта с формы заявки

- Форма шлёт POST на `/api/request` (`src/app/api/request/route.ts`), письмо
  уходит через собственный SMTP-клиент `src/lib/mail/smtp.ts` на
  `smtp.yandex.ru:465` от имени `SMTP_USER` на `MAIL_TO`.
- В письме — только заполненные поля заявки и две строки о согласии на
  обработку персональных данных (время, редакция документов, IP, ссылка на
  текст согласия). Это доказательство согласия по 152-ФЗ, убирать не стоит.
- **App Platform по умолчанию блокирует исходящие SMTP-порты.** Их открыла
  поддержка Timeweb по тикету **N12691219** (21.09.2026). Симптом блокировки —
  `SMTP: timeout` в логах приложения и ошибка «Не удалось отправить заявку»
  на сайте. Если повторится — писать в поддержку со ссылкой на тикет.
- Пароль приложения Яндекса: id.yandex.ru → Безопасность → Пароли приложений
  → «Почта». Если его сменить — обновить `SMTP_PASS` в панели.

## Защита от сканеров (инцидент 22.09.2026)

Боты нашли новый домен и засыпали сайт пробами уязвимости Next.js — запросами
с заголовком `Next-Action` (волна React2Shell). Сервер на одном ядре ушёл в
100 % CPU и завис так, что не отвечал даже на пинг; поддержка Timeweb
перезагружала машину вручную.

Что стоит теперь (`src/middleware.ts`):
- Сайт не использует Server Actions, поэтому любой запрос с `Next-Action`
  получает мгновенный 404 ещё до разбора тела.
- POST/PUT/DELETE принимает только `/api/request`; остальным — 404.
- Middleware видит все запросы, кроме файлов `_next/static/`.
- К рендеру допускаются только настоящие страницы (главная, about, contacts,
  legal, privacy на трёх языках), `/api/health`, `/api/request`,
  `/_next/image`, `/apple-icon` и карточки `/{язык}/opengraph-image/card`.
  Любой другой адрес получает заранее собранную фирменную 404 своего языка
  (`/{язык}/404`) — сервер отдаёт готовый файл, а не рендерит страницу.
- Обработчик картинок принимает только файлы из `/examples` и `/about`,
  качество 75 и ширины до 1536 px.
- Тело запроса — не больше 32 КБ (`middlewareClientMaxBodySize`), форма
  заявки: только JSON с того же сайта, 5 заявок с IP за 10 минут и 100 в час
  на весь сайт.
- `www` переадресуется на `pro-print.pro`; заголовки HSTS и CSP заданы в
  `next.config.mjs`.
- `/api/health` + проверка состояния в Timeweb = автоперезапуск при зависании.
- В Timeweb (Настройки веб-сервера) выставлен максимальный размер тела запроса.


## Работа с другого компьютера

```bash
git clone https://github.com/omariok/pro-print.git
cd pro-print
npm ci
npm run dev          # http://localhost:3000, без SMTP письма печатаются в консоль
npx tsc --noEmit     # проверка типов
npm run build        # то же, что делает Timeweb
```

Репозиторий приватный, поэтому для `clone`/`push` нужен вход в GitHub. Проще
всего через GitHub CLI: установить `gh` (https://cli.github.com), затем
`gh auth login --web` и `gh auth setup-git`. На Mac Omario `gh` лежит в
`~/.local/bin/gh` (Homebrew там без прав), в PATH его нет — вызывать по полному
пути или добавить `export PATH="$HOME/.local/bin:$PATH"`.

Обновить сайт = закоммитить и запушить в `main`. Дальше всё делает Timeweb.

## Если что-то сломалось

**Сайт не открывается.**
1. Статус Timeweb: https://timeweb.cloud/live (там же деградации сети по
   регионам) и Telegram `@timewebcloud_alerts`.
2. Панель приложения: статус («В сети» / «Деплой»), вкладка «Дашборд» —
   график CPU. Ровная полка 100 % = приложение зависло.
3. Кнопка перезапуска (↻) справа от названия. Если не помогает или во время
   деплоя она неактивна — чат поддержки в панели: попросить принудительно
   перезагрузить машину приложения ID 257655.
4. Медленно, но открывается: сравнить время первого байта и полной загрузки
   (`curl -o /dev/null -w "%{time_starttransfer} %{time_total}" https://pro-print.pro/`).
   Первый байт быстрый, а полная загрузка долгая — тормозит сеть хостинга,
   не сайт.

**Форма не отправляет.** «Логи приложения» → искать `[api/request]`.
`SMTP: timeout` — закрыт порт (см. выше). `535`/`authentication failed` —
неверный пароль приложения. `not_configured` — не заданы переменные.

**Деплой упал.** Вкладка «Деплой» → логи сборки. Локально `npm run build`
должен проходить чисто перед пушем.

**Домен показывает заглушку reg.ru.** DNS ещё не обновился или записи
сброшены — проверить таблицу выше; `dig +short pro-print.pro @1.1.1.1` должен
вернуть `194.87.133.155`.
